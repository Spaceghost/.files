# Gruvbox boot console

Date: 2026-09-08. Scope: every text-mode screen on the Oldbook (MacBookPro11,5,
Alpine edge, GRUB EFI, encrypted root) uses the Gruvbox Dark console palette and
a readable HiDPI font, without changing what the default boot entry boots.

## Decision

- The colours are kernel parameters, not a userspace step. `vt.default_red`,
  `vt.default_grn` and `vt.default_blu` take sixteen bytes each and are applied
  when the console is initialised and on every palette reset, so they cover the
  initramfs, kernel messages, the rescue gettys and any later VT the same way.
  The values are the Gruvbox terminal colours already used by Foot and Ghostty
  (`alpine/system/boot/console-palette.json`; a test keeps them equal to
  `foot.ini`). The default attribute becomes `vt.color=0x0F`, cream (`#ebdbb2`)
  on charcoal (`#282828`), instead of the kernel's grey-on-black `0x07`.
- The font is the kernel's built-in Terminus 16x32 (`CONFIG_FONT_TER16x32=y` in
  linux-lts 6.18.49), selected with `fbcon=font:TER16x32`. fbcon applies the
  named font to every framebuffer it binds, so the font survives the switch from
  simpledrm to i915. No console font package or `consolefont` service is
  needed; the service stays disabled and `/etc/conf.d/consolefont` is untouched.
- The rescue gettys print a Gruvbox masthead from `/etc/issue`, rendered from
  `alpine/system/boot/issue.template`. Only sixteen-colour SGR codes are used,
  so the banner takes its tones from the kernel palette. BusyBox getty treats
  both `\` and `%` as escape introducers; the renderer rejects percent signs
  and unknown escapes, and the template stays ASCII because the kernel font has
  256 glyphs.
- GRUB's own one-second menu is deliberately left in its default colours: its
  colour names cannot express the palette and the menu is visible for a second.

## Host changes (2026-09-08, backup `/var/backups/alpine-rice/boot-console-1788860524623373941`)

- `/etc/default/grub`: the five managed tokens appended to
  `GRUB_CMDLINE_LINUX_DEFAULT`; the root, cryptroot, cryptdm, modules, quiet and
  rootfstype tokens are unchanged.
- `/boot/grub/grub.cfg`: regenerated by `grub-mkconfig`, validated by
  `grub-script-check` and by the structural comparison in
  `boot_console.validate_generated_cfg`, then moved into place. The generated
  file also gained the empty `15_ostree` section that the installed
  `/etc/grub.d/15_ostree` symlink now contributes; it emits no entries.
- `/etc/issue`: replaced (the previous file belonged to `alpine-release`; an
  upgrade of that package may leave an `/etc/issue.apk-new` beside it).
- `/etc/conf.d/consolefont`: not changed; service not enabled.

## Rollback

```sh
doas alpine/bin/install-boot-console --rollback /var/backups/alpine-rice/boot-console-1788860524623373941
```

restores `/etc/default/grub`, `/etc/issue` and the previous `/boot/grub/grub.cfg`
byte for byte. Removing the five tokens from `/etc/default/grub` and running
`grub-mkconfig -o /boot/grub/grub.cfg` is the manual equivalent.

## Validation

- 15 unit tests in `alpine/tests/test_boot_console.py`: channel derivation,
  idempotent rewrite with stale-token replacement, refusal of quoted values,
  banner rendering and escape policy, entry derivation, structural validation
  accept/reject cases, init patching and shell syntax, backup/restore.
- `--dry-run` preview, real install, `grub-script-check` on the live file,
  and an idempotent second run that changed nothing.

## Unverified

No reboot was performed. The palette, font and banner are visible only at the
next boot; deferred fbcon takeover means the first console output (with
`quiet`, the passphrase prompt) is where the font and colours first appear.
