# Complete desktop themes

The user rejects palette-only themes and confirms that every theme must be a
complete desktop design. Both existing generated collections and future themes
need typography, geometry, window treatment, launcher presentation, widget
placement, application styling and matching artwork.

Keep functional configuration in the shared desktop source. Render each theme's
application profile from that source plus a validated design descriptor. Model
output supplies constrained design values, never executable configuration.
Existing authored Space Ghost and Gruvbox profiles remain editable. Generated
profiles are materialized before switching; failure must leave the selection
unchanged. The existing deployment journal owns HOME backups and recovery.

Preserve controls (including music rating), user content, quiet Conky policy,
Scripture restrictions and decoration preferences. The theme controls default
presentation, not these behavioral choices. Each generated collection retains
its artwork direction and existing paintings.

Validate distinct designs, reject incomplete definitions, exercise deployment
into disposable HOME, run theme and Conky tests, and parse rendered application
configuration. Capture isolated desktop evidence. Do not use actual song-rating
actions or request new provider artwork just to verify this change.
